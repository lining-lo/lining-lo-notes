## 2.开发模式介绍

我们介绍过，现在的企业项目开发有2种开发模式：前后台混合开发 和 前后台分离开发。

前后台混合开发，顾名思义就是前台后台代码混在一起开发。这种开发模式有如下缺点：

- 沟通成本高：后台人员发现前端有问题，需要找前端人员修改，前端修改成功，再交给后台人员使用

- 分工不明确：后台开发人员需要开发后台代码，也需要开发部分前端代码。很难培养专业人才

- 不便管理：所有的代码都在一个工程中

- 难以维护：前端代码更新，和后台无关，但是需要整个工程包括后台一起重新打包部署。

所以我们目前基本都是采用的前后台分离开发方式，如下图所示：

![](./images/image-20260928213438.png)

我们将原先的工程分为前端工程和后端工程这2个工程，然后前端工程交给专业的前端人员开发，后端工程交给专业的后端人员开发。

前端页面需要数据，可以通过发送异步请求，从后台工程获取。但是，我们前后台是分开来开发的，那么前端人员怎么知道后台返回数据的格式呢？后端人员开发，怎么知道前端人员需要的数据格式呢？

所以针对这个问题，我们前后台统一制定一套规范！我们前后台开发人员都需要遵循这套规范开发，这就是我们的 接口文档。接口文档有离线版和在线版本，接口文档示可以查询今天提供 资料/接口文档 里面的资料。

那么接口文档的内容怎么来的呢？是我们后台开发者根据产品经理提供的产品原型和需求文档所撰写出来的，产品原型示例可以参考今天提供资料/页面原型 里面的资料。

那么基于前后台分离开发的模式下，我们后台开发者开发一个功能的具体流程如何呢？如下图所示：

![](./images/image-20260928213439.png)

1. 需求分析：首先我们需要阅读需求文档，分析需求，理解需求。

2. 接口定义：查询接口文档中关于需求的接口的定义，包括地址，参数，响应数据类型等等

3. 前后台并行开发：各自按照接口文档进行开发，实现需求

4. 测试：前后台开发完了，各自按照接口文档进行测试

5. 前后段联调测试：前段工程请求后端工程，测试功能

![](./images/image-20260928213447.png)

Vue Router：Vue的官方路由。 为Vue提供富有表现力、可配置的、方便的路由。

Vue中的路由，主要定义的是路径与组件之间的对应关系。

比如，我们打开一个网站，点击左侧菜单，地址栏的地址发生变化。 地址栏地址一旦发生变化，在主区域显示对应的页面组件。 

![](./images/image-20260928213448.png)

![](./images/image-20260928213449.png)

VueRouter主要由以下三个部分组成，如下所示：

![](./images/image-20260928213450.png)

VueRouter：路由器类，根据路由请求在路由视图中动态渲染选中的组件

<router\-link\>：请求链接组件，浏览器会解析成\<a\>

\<router\-view\>：动态视图组件，用来渲染展示与路由路径对应的组件

## 2.页面交互

上述的数据，我们是在页面中写死了一组静态数据（来源于接口文档），那接下来呢，我们要将数据变成动态的，要动态从服务器端加载数据并返回，渲染展示在页面上。

页面交互的具体规则如下： 

1.页面加载完毕后，需要执行查询，查询部门列表数据。

2.点击搜索栏的搜索按钮后，需要执行查询，查询部门列表数据。

3.点击搜索栏的清空按钮后，需要清空搜索条件，并执行查询，查询部门列表数据。

4.在页码变化的时候，需要执行查询，查询部门列表数据。

5.在每页展示记录数发生变化的时候，需要执行查询，查询部门列表数据。

那么此时呢，我们就需要通过axios发送异步请求，请求服务器端加载数据。代码如下：

```vue
<script setup>
import { ref, onMounted } from 'vue'
import axios from 'axios'

// 查询参数
const queryParams = ref({
  name: '',
  status: '',
  page: 1,
  pageSize: 10
})

// 表格数据
const deptList = ref([])
const total = ref(0)

onMounted(() => {
  search()
})

// 查询按钮
const search = async () => {
  const result = await axios.get('/api/depts', { params: queryParams.value });
  if(result.data.code == 1){
    deptList.value = result.data.data.rows
    total.value = result.data.data.total
  }
}

// 重置查询
const clear = () => {
  queryParams.value = {
    name: '',
    status: '',
    page: 1,
    pageSize: 10
  }
  search()
}

const request = axios.create({
  baseURL: '/api',
  timeout: 600000
})

//axios的响应 response 拦截器
request.interceptors.response.use(
  (response) => { //成功回调
    return response.data
  },
  (error) => { //失败回调
    return Promise.reject(error)
  }
)

export default request
```

## 3.表单校验

Form 组件允许你验证用户的输入是否符合规范，来帮助你找到和纠正错误。`Form` 组件提供了表单验证的功能，只需为 `rules` 属性传入约定的验证规则，并将 `form-Item` 的 `prop` 属性设置为需要验证的特殊键值即可。

![](./images/image-20260928213501.png)

操作步骤：

- 通过ref属性注册元素的引用。

- 定义表单校验规则，通过rules属性与表单绑定，并通过prop属性绑定对应的表单项。

- 表单提交时，校验表单，校验通过，则允许提交表单。

![](./images/image-20260928213502.png)

1.定义表单引入 `deptFormRef`，及校验规则 `rules`

```javascript
// 表单校验
const deptFormRef = ref()
const rules = ref({
  name: [
    { required: true, message: '请输入部门名称', trigger: 'blur' },
    { min: 2, max: 10, message: '长度在 2 到 10 个字符', trigger: 'blur' }
  ],
  status: [
    { required: true, message: '请选择部门状态', trigger: 'change' }
  ]
})
```
