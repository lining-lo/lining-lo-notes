## 1.分析

![image\.png](./images/image-20260922160401.png)

通过页面原型，我们可以看到，在用户信息列表查询展示时，不仅要展示 姓名、用户名、头像、手机号、状态这些用户的基本信息，还要展示用户所属部门的部门名称、用户关联角色的角色名称等信息。

那这里要展示的用户基本信息数据来源于用户表 user，部门名称数据来源于部门表 dept，角色名称数据来源于角色表 role，所以这里会涉及到三张表的连接查询。

我们可以先一起借助于AI来完成sql语句的编写 （不考虑对应的查询条件）：

```sql
-- 查询所有的用户信息, 及其所属部门的部门名称, 关联角色的角色名称
/*
——交互说明——
1、搜索
1.1 用户姓名：请输入姓名，支持汉字的模糊搜索
1.2 手机号：根据手机号进行搜索，支持模糊搜索
1.3 部门：根据选择的部门进行查询
1.4 状态：正常、停用，根据选择的状态查询
1.5 查询结果，根据最后修改时间进行倒序排序
*/
select
    u.*,
    d.name as dept_name,
    r.name as role_name
from user u
    left join dept d on u.dept_id = d.id
    left join role r on u.role_id = r.id
where
    u.name like concat('%','张','%') 
    and u.phone like concat('%','138','%') 
    and u.status = 1 and u.dept_id = 2
order by u.update_time desc
```

```java
     * @return 分页结果
     * 注意：形参前面不能使用@RequestBody注解，因为该注解是接收请求体中的json数据，当前请求参数不在请求体中，也不是json数据，所以不能用。

        log.info("分页查询参数：{}" ,queryDto);
        //2 调用service层方法分页查询，得到PageResult分页结果
```

```java
/**
 * 用户服务实现类
 */
@Service
public class UserServiceImpl implements UserService {

    @Autowired
    private UserMapper userMapper;

    /**
     带条件分页查询
     @param queryDto 封装查询条件、当前页码、每页条数
     @return 分页结果
     */
    @Override
    public PageResult<User> page(UserQueryDto queryDto) {
        //1 设置分页参数(当前页码和每页条数)
        PageHelper.startPage(queryDto.getPage(),queryDto.getPageSize());
        //2 调用Mapper层方法，分页查询
        Page<User> page = (Page<User>)userMapper.list(queryDto);
        //3 获取分页结果封装成PageResult对象返回
        return new PageResult<>(page.getTotal(),page.getResult());
    }
}
```

5.UserMapper\.xml

存放模块 `qk-management`，存放位置 `resources/mapper`。代码如下：

```xml

<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "http://mybatis.org/dtd/mybatis-3-mapper.dtd" >
<mapper namespace="com.itheima.qk.mapper.UserMapper">

        from user u
            left join dept d on u.dept_id = d.id
            left join role r on u.role_id = r.id

            </if>
            <if test="phone != null and phone != ''">

            </if>
            <if test="deptId != null">
                and u.dept_id = #{deptId}
            </if>
        </where>
        order by u.create_time desc
    </select>
```

## 4.功能完善

### 4.1.分析

通过刚才的测试，我们可以看到用户的数据可以正常的添加，并录入到数据库中。

![image\.png](./images/image-20260923010140.png)

但是我们可以看到，用户的访问密码在数据库表中是以明文的形式存储的，这是非常不安全的，存在数据泄露的风险（任何人只要看到表中的数据，就能清楚的知道用户名和密码的信息了，就可以登录系统进行操作了） 。

所以，在项目开发中，数据库中的密码通常我们都会以密文（对明文进行加密）的形式进行存储的，确保数据的安全性，访问密码泄露的风险。

### 4.2.密码加密

密码加密的方式有很多，最为场景，使用最为广泛的当属MD5。

MD5：是一种信息摘要算法，一种被广泛使用的密码散列函数，可以产生出一个128位（16字节）的散列值，通常用于登录密码加密处理（只能加密不能解密）。

具体流程如下：

![image\.png](./images/image-20260923010141.png)

流程说明：

- 存储：在新增用户的时候，在往数据库保存用户信息的时候，要对明文的密码进行MD5加密，将加密后的密文存储再数据库表中。

- 查询：在用户登录的时候，输入密码，输入的是明文，那么此时我们要想验证用户输入密码的正确性，就可以把用户输入的明文进行MD5加密，然后再个数据库中查询出来的密文进行对比，如果一致，就说明密码正确。

接下来，我们就来完善新增用户的代码，在保存用户信息到数据库之前，对密码进行MD5加密，具体代码完善如下：

调整完善 `UserServiceImpl` 中的 `addUser` 方法。

```java
/**
 * 新增用户
 * @param user 用户信息
 */
@Override
public void add(User user) {
    //1 设置默认密码：用户名+123
    //user.setPassword(user.getUsername()+"123");
    //使用MD5算法对密码进行加密
    user.setPassword(DigestUtils.md5DigestAsHex((user.getUsername()+"123").getBytes()));
    //2 设置创建时间和更新时间为当前时间
    user.setCreateTime(LocalDateTime.now());
    user.setUpdateTime(LocalDateTime.now());
    //3 调用mapper层方法，保存用户
    userMapper.insert(user);
}
```

## 1.简介

文件上传，是指将本地图片、视频、音频等文件上传到服务器，供其他用户浏览或下载的过程。

文件上传在项目中应用非常广泛，我们经常发微博、发微信朋友圈都用到了文件上传功能。

上传文件的原始form表单，要求表单必须具备以下三点（上传文件页面三要素）：

- 表单必须有file域，用于选择要上传的文件

- 表单提交方式必须为POST：通常上传的文件会比较大，所以需要使用 POST 提交方式

- 表单的编码类型enctype必须要设置为：multipart/form\-data：普通默认的编码格式是不适合传输大型的二进制数据的，所以在文件上传时，表单的编码格式必须设置为multipart/form\-data

前端页面的3要素我们了解后，接下来我们就来验证下所讲解的文件上传3要素。

在提供的资料中有一个名叫 "文件上传" 的文件夹，直接将里的 `upload.html` 文件，复制到springboot项目工程下的static目录里面。

2.服务端代码形式如下

```java
package com.qk.controller;

import com.qk.common.Result;
import lombok.extern.slf4j.Slf4j;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.multipart.MultipartFile;
import java.io.File;

@Slf4j
@RestController
public class UploadController {

    /**
     * 文件上传
     */
    @PostMapping("/upload")
    public Result upload(String username, Integer age, MultipartFile file) throws Exception {
        log.info("上传文件开始...{}, {}, {}", username, age, file);
        file.transferTo(new File("D:/./images/" + file.getOriginalFilename()));
        return Result.success();
    }

}
```

在定义的方法中接收提交过来的数据 （方法中的形参名和请求参数的名字保持一致）

- 用户名：`String  name`

- 年龄： `Integer  age`

- 文件： `MultipartFile  file`

![image\.png](./images/image-20260923010146.png)

> Spring中提供了一个API：MultipartFile，使用这个API就可以来接收到上传的文件
>

问题1：如果表单项的名字和方法中形参名不一致，该怎么办？

```java
public Result upload(String username, 
                        Integer age,  
                        MultipartFile image) //image形参名和请求参数名file不一致
```

解决：使用@RequestParam注解进行参数绑定

```java
public Result upload(String username,
                     Integer age, 
                     @RequestParam("file") MultipartFile image)
```

## 2.本地存储

上面我们已经完成了文件上传最基本的功能实现，已经可以在服务端接收到上传的文件，并将文件保存在本地服务器的磁盘目录中了。 但是我们测试的时候发现，如果上传的文件名相同，后面上传的会覆盖前面上传的文件，那接下来，我们就要来优化这一块的功能。

代码实现如下：

```java
package com.qk.controller;

import com.qk.common.Result;
import lombok.extern.slf4j.Slf4j;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.multipart.MultipartFile;
import java.io.File;
import java.util.UUID;

@Slf4j
@RestController
public class UploadController {

    /**
     文件上传
     @param image 上传的图片
     */
    @PostMapping("/upload")
    public Result upload(MultipartFile image) throws IOException {
        //log.info("上传文件：{}", image.getOriginalFilename());
        //1 获取原始文件名
        String filename = image.getOriginalFilename();  //例如：a.jpg
        //2 需求：生成唯一文件名
        //2.1 使用Java提供的UUID工具类生成一个唯一32位字符串。例如：23nnsd5-sk429sdf-234s8
        String uuid = UUID.randomUUID().toString();
        //2.2 获取原始文件名中的后缀名
        //int index = filename.lastIndexOf(".");
        String suffix = filename.substring(filename.lastIndexOf("."));
        //2.3 将唯一字符串+后缀名组成新的文件名
        filename = uuid + suffix;
        //3 将客户端上传的图片保存到指定的目录中
        image.transferTo(new File("D:/upload", filename));
        return Result.success("D:/upload/" + filename);
    }
}
```

> MultipartFile 常见方法： 
> 
> - `String  getOriginalFilename();`  //获取原始文件名
> 
> - `void  transferTo(File dest);`` `   //将接收的文件转存到磁盘文件中
> 
> - `long  getSize();`   //获取文件的大小，单位：字节
> 
> - `byte[]  getBytes();`` `   //获取文件内容的字节数组
> 
> - `InputStream  getInputStream();`    //获取接收到的文件内容的输入流
> 

利用 `Apifox` 测试，注意：请求参数名和controller方法形参名保持一致。

![image\.png](./images/image-20260923010147.png)

通过 `Apifox` 测试，我们发现文件上传是没有问题的。

在解决了文件名唯一性的问题后，我们再次上传一个较大的文件\(超出1M\)时发现，后端程序报错：

![image\.png](./images/image-20260923010148.png)

报错原因呢，是因为：在SpringBoot中，文件上传时默认单个文件最大大小为1M

那么如果需要上传大文件，可以在 `application.properties` 进行如下配置：

```yaml
spring：
    servlet:
      multipart:
        max-file-size: 10MB #单个文件最大10MB
        max-request-size: 100MB #请求总大小最大100MB
```

> 说明：
>
> max\-file\-size：表示单个文件最大大小。
>
> max\-request\-size：表示单个请求最大大小。
>

到时此，我们文件上传的本地存储方式已完成了。但是这种本地存储方式还存在一问题： 

![image\.png](./images/image-20260923010149.png)

如果直接存储在服务器的磁盘目录中，存在以下缺点：

- 不安全：磁盘如果损坏，所有的文件就会丢失

- 容量有限：如果存储大量的图片，磁盘空间有限\(磁盘不可能无限制扩容\)

- 无法直接访问

为了解决上述问题呢，通常有两种解决方案：

- 自己搭建存储服务器，如：fastDFS 、MinIO

- 使用现成的云服务，如：阿里云，腾讯云，华为云

```java
import com.aliyun.oss.*;
import com.aliyun.oss.common.auth.*;
import com.aliyun.oss.common.comm.SignVersion;
import com.aliyun.oss.model.PutObjectRequest;
import com.aliyun.oss.model.PutObjectResult;
import java.io.File;

public class Demo {

    public static void main(String[] args) throws Exception {
        // Endpoint以华东1（杭州）为例，其它Region请按实际情况填写。
        String endpoint = "https://oss-cn-hangzhou.aliyuncs.com";
        // 从环境变量中获取访问凭证。运行本代码示例之前，请确保已设置环境变量OSS_ACCESS_KEY_ID和OSS_ACCESS_KEY_SECRET。
        EnvironmentVariableCredentialsProvider credentialsProvider = CredentialsProviderFactory.newEnvironmentVariableCredentialsProvider();
        // 填写Bucket名称，例如examplebucket。
        String bucketName = "qk-parent-zz";
        // 填写Object完整路径，完整路径中不能包含Bucket名称，例如exampledir/exampleobject.txt。
        //String objectName = "aaa/a.jpg"; //文件在bucket桶中的路径+名称.此处会创建一个aaa目录，a.jpg存到这个目录中
        String objectName = "a.jpg"; //文件在bucket桶中的路径+名称
        // 填写本地文件的完整路径，例如D:\\localpath\\examplefile.txt。
        // 如果未指定本地路径，则默认从示例程序所属项目对应本地路径中上传文件流。
        String filePath= "D:/image/a.jpg";  //要上传的文件路径
        // 填写Bucket所在地域。以华东1（杭州）为例，Region填写为cn-hangzhou。
        String region = "cn-hangzhou";
        
        // 创建OSSClient实例。
        // 当OSSClient实例不再使用时，调用shutdown方法以释放资源。
        ClientBuilderConfiguration clientBuilderConfiguration = new ClientBuilderConfiguration();
        clientBuilderConfiguration.setSignatureVersion(SignVersion.V4);        
        OSS ossClient = OSSClientBuilder.create()
        .endpoint(endpoint)
        .credentialsProvider(credentialsProvider)
        .clientConfiguration(clientBuilderConfiguration)
        .region(region)               
        .build();

        try {
            InputStream inputStream = new FileInputStream(filePath);
            // 创建PutObjectRequest对象。
            PutObjectRequest putObjectRequest = new PutObjectRequest(bucketName, objectName, inputStream);
            // 创建PutObject请求。
            PutObjectResult result = ossClient.putObject(putObjectRequest);
        } catch (OSSException oe) {
            System.out.println("Caught an OSSException, which means your request made it to OSS, "
                    + "but was rejected with an error response for some reason.");
            System.out.println("Error Message:" + oe.getErrorMessage());
            System.out.println("Error Code:" + oe.getErrorCode());
            System.out.println("Request ID:" + oe.getRequestId());
            System.out.println("Host ID:" + oe.getHostId());
        } catch (ClientException ce) {
            System.out.println("Caught an ClientException, which means the client encountered "
                    + "a serious internal problem while trying to communicate with OSS, "
                    + "such as not being able to access the network.");
            System.out.println("Error Message:" + ce.getMessage());
        } finally {
            if (ossClient != null) {
                ossClient.shutdown();
            }
        }
    }
} 
```

> 切记，大家需要将上面的 `endpoint` ，`bucketName`，`objectName`，`file` 都需要改成自己的。

> 在以上代码中，需要替换的内容为：
>
> - endpoint：阿里云OSS中的bucket对应的域名
>
> - bucketName：Bucket名称
>
> - objectName：对象名称，在Bucket中存储的对象的名称
>
> - file：文件路径
>

## 4.功能优化

员工管理的新增功能我们已开发完成，但在我们所开发的程序中还一些小问题，下面我们就来分析一下当前案例中存在的问题以及如何优化解决。

在刚才我们制作的AliyunOSS操作的工具类中，我们直接将 endpoint、bucketName参数直接在java文件中写死了。如下所示：

### 4.1.@Value

那么对于这些容易变动的参数，我们可以将其配置在配置文件中，然后通过 `@Value` 注解来注解外部配置的属性。如下所示：

![image\.png](./images/image-20260923010219.png)

具体实现代码如下：

1.application\.yml

```yaml
#阿里云OSS
aliyun:
  oss:
    endpoint: https://oss-cn-hangzhou.aliyuncs.com
    bucketName: qk-parent-zxy
    region: cn-hangzhou
```

2.AliyunOSSOperator

```java
@Slf4j
@Component
public class AliyunOSSOperator {

    //需求：读取yml文件中的配置信息赋值给成员变量
    //方式一：使用@Value("${key}")将属于一个一个注入给成员变量
    @Value("${aliyun.oss.endpoint}")

```

### 4.2.@ConfigurationProperties

如果只有一两个属性需要注入，而且不需要考虑复用性，使用`@Value`注解就可以了。

但是使用@Value注解注入配置文件的配置项，如果配置项多，注入繁琐，不便于维护管理 和 复用。如下所示:

![image\.png](./images/image-20260923010220.png)

那么有没有一种方式可以简化这些配置参数的注入呢？答案是肯定有，在Spring中给我们提供了一种简化方式，可以直接将配置文件中配置项的值自动的注入到对象的属性中。

Spring提供的简化方式套路：

1.需要创建一个实现类，且实体类中的属性名和配置文件当中key的名字必须要一致

比如：配置文件当中叫endpoint，实体类当中的属性也得叫endpoint，另外实体类当中的属性还需要提供 getter / setter方法

2.需要将实体类交给Spring的IOC容器管理，成为IOC容器当中的bean对象

3.在实体类上添加`@ConfigurationProperties`注解，并通过perfect属性来指定配置参数项的前缀

![image\.png](./images/image-20260923010221.png)

具体实现步骤:

1.定义实体类 `AliyunOSSProperties` ，并交给IOC容器管理

在 `qk-common` 模块的 `com.qk.utils` 包中定义。

```java
@Data
@Component
//将会aliyun.oss下的所有配置信息按照成员变量的名字自动封装。例如：配置中的endpoint 封装到endpoint 属性身上
@ConfigurationProperties(prefix = "aliyun.oss")  
public class AliyunOSSProperties {
    private String endpoint;
    private String bucketName;
    private String region;
}
```

Mybatis中动态sql标签\<foreach\>的作用及用法。

作用：循环、遍历

属性：

- `collection`：遍历的数组、集合名字

- `item`：遍历出来的元素

- `open`：循环开始前，拼接的sql片段

- `close`：循环结束后，拼接的sql片段

- `separator`：每次循环之间的间隔符
