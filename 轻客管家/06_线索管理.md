> 线索：线索是未经验证的潜在客户。是与客户初次接触获得的原始信息，可以是从B站、抖音、小红书、快手等线上渠道获取到的手机号码，也可以是在大学宣讲、线下推广等渠道获取到的客户的简单信息（手机号、微信、QQ等），然后通过管理、跟进、转化为最终客户。
>

> 商机：商机是已验证的、有较高成交潜力的客户，通常已明确表达需求或购买意向。
>

> 客户：已与企业发生实际交易或签订合同的主体，即“付费用户”。
>

### 5.1.分析

![image\.png](./images/image-20260925090734.png)

通过页面原型，可以看到，线索列表数据查询时，既要查询线索的基本信息，还需要查询线索的归属人姓名，所以这里呢，就会涉及到多表查询，基础sql如下：

```sql
-- 根据线索ID、手机号、状态、线索来源、线索归属人姓名，来查询线索基本信息 及 线索归属人姓名
select c.*,u.name as assign_name
from clue c left join user u on c.user_id = u.id
where
    c.id=?
    and c.phone like concat('%',?,'%')
    and c.status=?
    and c.channel=?
    and u.name like concat('%',?,'%')
```

```java
@Autowired
private ClueMapper clueMapper;
/**
 * 根据条件分页查询
 * @param clueQueryDto 封装分页条件
 */
@Override
public PageResult<Clue> pageQuery(ClueQueryDto clueQueryDto) {
    //1 设置分页参数
    Page<Clue> page = new Page<>(clueQueryDto.getPage(), clueQueryDto.getPageSize());
    //2 调用mapper层方法，分页查询
    Page<Clue> p=clueMapper.list(page, clueQueryDto);
    //3 封装分页结果
    return new PageResult<Clue>(p.getTotal(), p.getRecords());
}
```

4.在 `resources` 目录下新增配置文件 `ClueMapper.xml`，具体配置如下：

```xml
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "http://mybatis.org/dtd/mybatis-3-mapper.dtd" >
<mapper namespace="com.itheima.qk.mapper.ClueMapper">

    <!-- 线索列表 线索状态(status)，1:待分配，2:待跟进，3:跟进中，4:伪线索，5:转为商机-->
    <!--分页动态查询线索-线索列表查询
     @param clueQueryDto 封装查询条件和分页参数
    Page<Clue> list(Page<Clue> page, ClueQueryDto clueQueryDto);-->
    <select id="list" resultType="com.itheima.qk.entity.Clue">
        select c.*, u.name as assign_name 
        from clue c left join user u on c.user_id = u.id
        <where>
            <if test="clueQueryDto.clueId != null">
                and c.id = #{clueQueryDto.clueId}
            </if>
            <if test="clueQueryDto.phone != null and clueQueryDto.phone != ''">
                and c.phone LIKE concat('%',#{clueQueryDto.phone},'%')
            </if>
            <if test="clueQueryDto.status != null">
                and c.status = #{clueQueryDto.status}
            </if>
            <if test="clueQueryDto.channel != null">
                and c.channel = #{clueQueryDto.channel}
            </if>
            <if test="clueQueryDto.assignName != null and clueQueryDto.assignName != ''">
                and u.name like concat('%', #{clueQueryDto.assignName}, '%')
            </if>
        </where>
        order by c.update_time desc
    </select>
```

# 二、线索跟进

线索跟进是指，管理员将线索分配给指定的线索专员后，线索专员会及时跟进这个线索的情况，并将跟进情况记录在跟进记录表中。 

![image\.png](./images/image-20260925091554.png)

线索跟进时，跟进的信息包括：意向学科、意向等级、下次跟进时间、跟进记录等信息。而一个线索，可以被跟进人多次跟进：

- 如果在线索跟进过程中，发现这个线索，没有意向，可以点击 “伪线索” 将线索标记为伪线索。

- 如果在线索跟进过程中，发现这个线索，有强烈的意向，可以点击 “转商机” 将线索转为商机，有商机专员进一步跟进最终转客户、成交。

那么对于我们接下来，要完成的线索跟进功能来说，其实需要分为两步实现：

- 查询回显：查询线索的基本信息、线索的跟进记录列表，回显在页面中。

- 线索跟进：录入本次跟进信息后，点击确定，跟进此线索。

> 在这种一对多的查询中，我们要想成功的封装的结果，需要手动的基于 `<resultMap>` 来进行封装结果。
>
> Mybatis中封装查询结果，什么时候用 `resultType`，什么时候用 `resultMap` ？
>
> - 如果查询返回的字段名与实体的属性名可以直接对应上，用`resultType` 。
>
> - 如果查询返回的字段名与实体的属性名对应不上，或实体属性比较复杂，可以通过`resultMap`手动封装 。
>

> `resultMap`手动映射封装的规则 ？
>
> - `autoMapping="true"`：字段名和属性名相同或者符合驼峰命名规则就自动映射
>
> - `id`主键属性就使用 `<id property="id" column="id"/>` 标签。
>
> - 其他普通属性，就使用 `<result property="phone" column="phone"/>` 标签。
>
> - 集合属性就使用 `<collection property="trackRecords" ofType="com.qk.entity.ClueTrackRecord">` 标签，其中的 `ofType` 属性表示集合中的单条记录的类型。
>

### 3.2.介绍

概念： 事务是一组操作的集合，它是一个不可分割的工作单位。事务会把所有的操作作为一个整体一起向系统提交或撤销操作请求，即这些操作 要么同时成功，要么同时失败。

就拿线索跟进的这个业务为例，在这个业务操作中，包含了两个操作，那这两个操作是一个不可分割的工作单位。

![image\.png](./images/image-20260925091606.png)

这两个操作，要么同时失败，要么同时成功。

> 默认Mysql的事务是自动提交的，也就是说，当执行一条DML语句，Mysql会立即隐式的提交事务。
>

### 3.3.操作

事务控制主要三步操作：开启事务、提交事务/回滚事务。

- 需要在这组操作执行之前，先开启事务  \( `start transaction; / begin;`\)。

- 所有操作如果全部都执行成功，则提交事务 \( `commit;` \)。

- 如果这组操作中，有任何一个操作执行失败，都应该回滚事务 \( `rollback` \)。

那接下来，我们就可以将线索跟进的业务操作，进行事务管理。 具体的sql如下：

```sql
-- 开启事务
start transaction; / begin;

-- 1. 更新线索基本信息
update clue set subject  = 1, level = 1, next_time = '2025-07-10 10:00:00', update_time = '2025-07-09 10:05:00' where id = 8;

-- 2. 添加线索的跟进记录
insert into clue_track_record (clue_id, user_id, subject, level, record, next_time, type, false_reason, create_time)
      values (8, 1, 1, 1, '用户有意向,正在考虑', '2025-07-10 10:00:00', 1, null, '2025-07-09 10:05:00'); 

-- 提交事务(全部成功) / 回滚事务(有任何一个失败)
commit; / rollback;
```

事务管理的场景，是非常多的，比如：

- 银行转账

- 下单扣减库存

### 5.1.分析

在上述实现的线索跟进的功能中，一旦在更新线索基本信息后出现异常。 我们就会发现，线索信息更新成功，但是线索跟进记录保存失败，造成了数据的不完整不一致。

### 5.2.Transactional注解

注解：@Transactional

作用：就是在当前这个方法执行开始之前来开启事务，方法执行完毕之后提交事务。如果在这个方法执行的过程当中出现了异常，就会进行事务的回滚操作。

位置：业务层的方法上、类上、接口上

- 方法上：当前方法交给spring进行事务管理

- 类上：当前类中所有的方法都交由spring进行事务管理 

- 接口上：接口下所有的实现类当中所有的方法都交给spring 进行事务管理

接下来，我们就可以在线索跟进业务方法上加上 `@Transactional` 来控制事务 。

### 5.4.事务四大特性

面试题：事务有哪些特性？

- 原子性（Atomicity）：事务是不可分割的最小单元，要么全部成功，要么全部失败。

- 一致性（Consistency）：事务完成时，必须使所有的数据都保持一致状态。

- 隔离性（Isolation）：数据库系统提供的隔离机制，保证事务在不受外部并发操作影响的独立环境下运行。

- 持久性（Durability）：事务一旦提交或回滚，它对数据库中的数据的改变就是永久的。

> 事务的四大特性简称为：ACID
>

![image\.png](./images/image-20260925091616.png)

1.原子性（Atomicity） ：原子性是指事务包装的一组sql是一个不可分割的工作单元，事务中的操作要么全部成功，要么全部失败。

2.一致性（Consistency）：一个事务完成之后数据都必须处于一致性状态。

如果事务成功的完成，那么数据库的所有变化将生效。

如果事务执行出现错误，那么数据库的所有变化将会被回滚\(撤销\)，返回到原始状态。

3.隔离性（Isolation）：多个用户并发的访问数据库时，一个用户的事务不能被其他用户的事务干扰，多个并发的事务之间要相互隔离。

一个事务的成功或者失败对于其他的事务是没有影响。

4.持久性（Durability）：一个事务一旦被提交或回滚，它对数据库的改变将是永久性的，哪怕数据库发生异常，重启之后数据亦然存在。

### 5.2.Thread线程

**介绍**

线程（Thread） ：是操作系统能够进行运算调度的最小单位。它被包含在进程之中，是进程中的实际运行单位。

进程（Process）：是操作系统中的一个核心概念，指的是正在执行的程序实例，是系统进行资源分配和调度的基本单位。

![image\.png](./images/image-20260925091618.png)

那在我们的操作系统中，会运行很多的应用软件，而这些应用软件在运行的时候，就会在操作系统中启动一个进程，比如我们电脑上安装的百度网盘、IDEA、Apifox、Sublime、微信、QQ、360等等，我们可以打开我们的电脑的资源管理器，就可以看到这些个进程。

![image\.png](./images/image-20260925091619.png)

而在一个进程中，会运行很多个线程来处理不同的任务，而这些个线程会公用一个CPU来进行任务处理。

> 为什么要使用多线程呢？
>
> 目的就是为了让程序能同时处理多个任务，提升效率，并充分利用系统资源。
>

那我们java程序运行，需不需要线程呢，答案是肯定的。

那其实，当我们编写一个main方法运行时，程序默认就会自动一个主线程来执行这个程序。如果说，我们需要创建另外一个独立的线程来执行任务，就可以基于java中提供的API来创建线程。

**创建线程**

方式一：继承Thread类

创建一个类，继承Thread，重写run方法 。

```java
package com.qk;

public class MyThread extends Thread{
    @Override
    public void run() {
        System.out.println(this.getName() + " : 执行任务啦....");
    }
}
```

测试：

```java
package com.qk;

public class ThreadDemo {
    public static void main(String[] args) {
        Thread t1 = new MyThread(); //创建线程
        t1.start(); //启动线程
    }
}
```

> 注意事项:  启动线程必须是调用start方法，不是调用run方法。
>
> 如果直接调用run方法就不认为是一条线程启动了，而是把Thread当做一个普通对象，此时run方法中      的执行的代码会成为主线程的一部分。
>

方式二：实现Runnable接口

创建一个类，实现Runnable接口，实现run方法 。

```java
package com.qk;

public class MyRunnable implements Runnable {
```

接下来，我们学习线程的第三种创建方式。已经有两种了为什么还有要第三种呢？ 

这样，我们先分析一下前面两种都存在的一个问题。

如果线程执行完毕后有一些数据需要返回，他们重写的run方法均不能直接返回结果。

怎么解决这个问题呢?

JDK5提供了Callable接口和FutureTask类来创建线程，它最大的优点就是有返回值。

方式三：实现Callable接口

创建一个类，实现Runnable接口，实现run方法 。

```java
package com.qk;

import java.util.concurrent.Callable;

public class MyCallable implements Callable<String> {

    private int num;
    public MyCallable(int num) {
        this.num = num;
    }

    @Override
    public String call() throws Exception {
        System.out.println(Thread.currentThread().getName() + " : 执行任务...");
        int result = 0;
        for (int i = 0; i < num; i++) {
            result += i;
        }
        return "任务执行完毕, 计算 1-" + num + " 的和为: " + result;
    }
}
```

多线程的应用场景:

以上是线程创建的三种方式，但是其实在项目开发中，即使我们要使用多个线程来执行任务，我们一般也不推荐使用上述的三种方式来创建线程，因为创建线程是比较消耗资源的，而上述的方式创建线程，每一次都是创建一个新的线程来执行任务，任务执行完毕，线程也就被销毁了。而频繁的创建线程，销毁线程，是非常耗费系统资源的，所以项目开发中一般不会使用这三种方式创建线程，而是会使用线程池技术。

### 5.3.线程池

**介绍**

其实，线程池就是一个可以复用线程的技术。

而使用线程池，就可以解决上面的问题。

如下图所示，线程池内部会有一个容器，存储几个核心线程，假设有3个核心线程，在执行任务的时候，就可以使用这3个核心线程可以处理任务，可以做到线程的复用。

![image\.png](./images/image-20260925091620.png)

线程池的使用步骤：

1.创建线程池 \(Executors工具类快速创建\)

2.提交任务

3.任务执行完毕，关闭线程池（项目开发中一般不关闭）

示例代码如下：

```java
package com.qk;

import java.util.Random;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class ThreadPoolDemo {
    public static void main(String[] args) {
        //1. 创建线程池
        ExecutorService executor = Executors.newFixedThreadPool(5);
        
        //2. 提交任务
        for (int i = 0; i < 100; i++) {
            executor.submit(() -> {
                try {
                    Thread.sleep(new Random().nextInt(2000));
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
                System.out.println(Thread.currentThread().getName() + "   正在执行任务");
            });
        }
        
        //3. 关闭线程池
        executor.shutdown();
    }
}
```

**线程池核心参数**

![image\.png](./images/image-20260925091622.png)

> 在线程池中涉及到7个核心参数，分别是：
>
> 1.`int corePoolSize`：核心线程数，核心线程会常驻线程池
>
> 2.`int maximumPoolSize`：最大线程数，如果同时执行的任务数超过了核心线程数，且队列已满，会创建新的线程来救急，不超这个最大线程数
>
> 3.`long keepAliveTime`：存活时间，超过核心线程数的线程一旦闲下来，会存活一段时间，然后被销毁
>
> 4.`TimeUnit unit`：时间单位
>
> 5.`BlockingQueue<Runnable> workQueue`：工作队列，如果同时执行的任务数超过了核心线程数，会把暂时无法处理的任务放入此队列
>
> 6.`ThreadFactory threadFactory`：线程工厂，可以控制池中线程的命名规则，是否是守护线程等（不太重要的参数）
>
> 7.`RejectedExecutionHandler handler`：拒绝策略，队列放满任务，且所有线程都被占用，再来新任务，就会有问题：
>
> - `AbortPolicy` 报错策略，直接抛异常
>
> - `CallerRunsPolicy` 推脱策略，线程池不执行任务，推脱给任务提交线程
>
> - `DiscardOldestPolicy` 抛弃最老任务策略，把队列中最早的任务抛弃，新任务加入队列等待
>
> - `DiscardPolicy` 抛弃策略，直接把新任务抛弃不执行

自定义线程池：

```java
package com.qk;

import java.util.Random;
import java.util.concurrent.ArrayBlockingQueue;
import java.util.concurrent.Executors;
import java.util.concurrent.ThreadPoolExecutor;
import java.util.concurrent.TimeUnit;

public class ThreadPoolDemo {
    public static void main(String[] args) {
        //1. 创建线程池
        ThreadPoolExecutor executor = new ThreadPoolExecutor(
                5, // 核心线程数
                10, // 最大线程数
                1000,// 线程空闲时间
                TimeUnit.SECONDS, // 线程空闲时间单位
                new ArrayBlockingQueue<>(10), // 线程队列
                Executors.defaultThreadFactory(), // 线程工厂
                new ThreadPoolExecutor.AbortPolicy()); // 拒绝策略 - 报错
        
        //2. 提交任务
        for (int i = 0; i < 100; i++) {
            executor.submit(() -> {
                try {
                    Thread.sleep(new Random().nextInt(2000));
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
                System.out.println(Thread.currentThread().getName() + "   正在执行任务");
            });
        }
        
        //3. 关闭线程池
        executor.shutdown();
    }

}
```

### 5.4.ThreadLocal

ThreadLocal 并不是一个Thread，而是Thread的局部变量。

ThreadLocal为每个线程提供一份单独的存储空间，具有线程隔离的效果，不同的线程之间不会相互干扰。

![image\.png](./images/image-20260925091624.png)

常见方法：

- `public void set(T value) `  设置当前线程的线程局部变量的值

- `public T get() `                    返回当前线程所对应的线程局部变量的值

- `public void remove() `       移除当前线程的线程局部变量

```java
package com.qk.filter;

import jakarta.servlet.annotation.WebFilter;

@Slf4j
@WebFilter(urlPatterns = "/*")
public class TokenFilter implements Filter {

    @Override
    public void doFilter(ServletRequest servletRequest, ServletResponse servletResponse, FilterChain chain) throws IOException, ServletException {

        HttpServletRequest request = (HttpServletRequest) servletRequest;
        HttpServletResponse response = (HttpServletResponse) servletResponse;

        // 放行登录接口
        if ("/login".equals(request.getRequestURI())) {
            log.info("登录操作, 直接放行");
            chain.doFilter(request, response);
            return;
        }

        // 提取请求头中的 token
        String token = request.getHeader("token");
        if (token == null || token.isEmpty()) {
            log.info("请求头中没有 token, 拒绝访问, 401");
            response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
            return;
        }

        try {
            // 解析 token
            Claims claims = JwtUtils.parseToken(token);
            //获取用户id, 存入ThreadLocal
            Integer userId = claims.get("id", Integer.class);
            CurrentUserHoler.setCurrentUser(userId);
        } catch (Exception e) {
            // 捕获解析 token 异常，返回 401 错误
            log.info("解析 token 出错, 拒绝访问, 401");
            response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
            return;
        }

        // 继续执行后续过滤器或请求处理
        log.info("token 正确, 继续执行后续过滤器或请求处理");
        chain.doFilter(request, response);

        //用户删除
        CurrentUserHoler.removeCurrentUser();
    }

}
```
